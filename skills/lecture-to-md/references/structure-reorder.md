# 结构重排（汇总之后、交付之前）

> **谁做**：主代理，且必须**重新对照文字稿**，不能只看 `notes.md` 自己改自己。
> **改什么**：只有标题行。
> **不改什么**：正文一个字都不动。

---

## 0. 适用范围与分工

**诊断可以请子代理帮忙，判断与执行一律留主代理。**

| 场景                 | 诊断                  | 拍板 + 执行 |
| ------------------ | ------------------- | ------- |
| 5-A 单线程（≤ 30 分钟）   | 主代理跑脚本自查            | 主代理     |
| 5-B 且 H1 < 5 个     | 主代理跑脚本自查            | 主代理     |
| **5-B 且 H1 ≥ 5 个** | **诊断子代理提案 + 主代理复核** | 主代理     |

H1 少于 5 个时结构问题一眼可见，派子代理的往返成本大于收益。H1 多了以后，主代理既看不过来，又容易锚定在自己当初定的骨架上——这才值得请一个**没参与过切分**的子代理来提反对意见。

> **为什么不让子代理直接改**：判断真实母题需要全局视野（见第 4 节），而子代理手上只有切片。执行权交出去，等于让一个没看过全稿的人去定整门课的结构。

---

## 1. 为什么需要这一环

H1 骨架是在**读完全稿之后、动笔之前**一次性拍板的。这个时间点有个天然缺陷：主代理当时只看到素材分布，还没看到内容写出来之后的真实粒度；同时为了让每个子代理工作量均衡，很容易不自觉地做了两件错事——

- 把**过大的主题拆散**成几个 H1（因为它一个人写不完）；
- 把**过小的主题合并**进邻居（因为它撑不起一个 H1）。

结果就是：最终的 H1 反映的是「**切分块**」，而不是「**课程结构**」。笔记读起来会像是几篇拼起来的短文，而不是一门课。

这一环就是把这个失真修回来：**让标题层级回到老师真实的授课结构上。**

---

## 2. 诊断：哪些迹象说明结构坏了

### 2.1 主代理自查（必做，两档都要跑）

主代理对着标题骨架逐条自查，命中任意一条都应该重排：

| # | 迹象                                     | 说明                |
| - | -------------------------------------- | ----------------- |
| 1 | H1 名称里带**子层级编号**（如「2.3 注意力」「B2 编码器」）   | 它其实是别人的二级标题       |
| 2 | H1 名称带**续接词**：「…（续）」「再谈…」「…的其余部分」「…补充」 | 同一个主题被切断了         |
| 3 | **相邻多个 H1 语义上同属一个母题**                  | 母题被拆成了并列块         |
| 4 | 各 H1 **字数量级悬殊**（最短的不足最长的 1/5）          | 层级错位：小的应是 H2，大的该拆 |
| 5 | H1 是**具体技术点**而非主题块（如「Softmax 的温度系数」）   | 它应待在某个主题块的下面      |
| 6 | 同一个母题名词在**多个 H1 里反复出现**                | 该母题被切碎了           |
| 7 | H1 的命名风格不统一（有的像章节名，有的像小节名）             | 层级标准漂移            |

命令辅助（打印标题骨架 + 每个标题下的字数，第 3、4 条一眼就能看出来）：

```bash
python3 - <<'PY'
import re
src = open('notes.md', encoding='utf-8').read()   # 换成实际的 {title_name}.md
lines, out, cur, buf = src.split('\n'), [], None, []
def flush():
    if cur: out.append((cur[0], cur[1], len(''.join(buf))))
for l in lines:
    m = re.match(r'^(#{1,4})\s+(.*)', l)
    if m:
        flush(); cur = (len(m.group(1)), m.group(2)); buf = []
    else:
        buf.append(l)
flush()
for lv, t, n in out:
    print(f"{'  ' * (lv - 1)}{'#' * lv} {t}   [{n} 字]")
PY
```

只想看骨架：

```bash
grep -n "^#\{1,4\} " "{title_name}.md"
```

### 2.2 派诊断子代理（仅 5-B 且 H1 ≥ 5）

主代理自查完，如果 H1 ≥ 5 个，**再**派一个诊断子代理独立看一遍。

自己查自己有个绕不过去的毛病：骨架是你定的，你很难推翻自己；加上到这一步已经读了几万字的稿子和笔记，对「这串 H1 读起来像不像一门课」的判断会钝化。子代理没参与过切分，既没有沉没成本，也没有上下文疲劳。

**关键：不给它全文，只给「结构信号包」。** 母题识别靠的是路标句和段落边界，不是逐字精读，所以这个包信息密度极高、体积极小——绕开了「要全局视野就必须塞全文」的矛盾。

```text
派发给诊断子代理的内容：

① 标题骨架
   grep -n "^#\{1,4\} " "{title_name}.md" 的输出

② 字数统计
   2.1 节脚本的输出（哪个 H1 特别短/特别长，一眼可见）

③ 路标句（稿子原文 + 上下文各 2 行）
   见下方提取命令

④ 每个 part 边界处的稿子原文（前后各 10 行）
   判断该处是不是真的主题切换点

⑤ 课件目录页 / 章节分隔页（有课件时）
   合订 PDF 常常已经给出了权威的大块划分
```

路标句提取（中英通用，命中即带上下文输出）：

```bash
python3 - <<'PY'
import re
pats = (r'我们今天|今天要讲|下面进入|接下来.{0,8}看|第[一二三四五六七八九十][部点个章]|'
        r'有[一二三四五六七八九十]个|分为[一二三四五六七八九十]|回过头|回到.{0,6}来看|'
        r'刚才|前面讲过|再补充|总结一下|'
        r'today we|next section|part (one|two|three)|moving on|going back to|as I said')
lines = open('transcript.txt', encoding='utf-8').read().split('\n')
for i, l in enumerate(lines):
    if re.search(pats, l, re.I):
        print(f'--- L{i+1} ---')
        for j in range(max(0, i - 2), min(len(lines), i + 3)):
            print(f'{j+1}: {lines[j]}')
PY
```

**子代理只输出提案，不碰文件。** 产出格式：

```markdown
## 诊断提案

### 疑似问题
1. H1「2.3 注意力机制」带子层级编号 → 实为某母题下的小节
2. H1「编码器（续）」与前面的「编码器」是同一主题被切断
3. B1…B6 六个 H1 都在讲 B 的不同情形 → B 才是母题

### 建议映射表
| 旧标题（旧层级）       | 新标题（新层级）    | 依据（稿子位置 + 原文摘录）                    |
| -------------- | ------------ | ---------------------------------- |
| `# 2.3 注意力机制`  | `## 注意力机制`   | L812「X 有三个要点」的第三点，属「编码器」母题       |
| `# 编码器（续）`     | `## 编码器（续）`  | L1540「刚才那个编码器，我们再补充一点」→ 非新主题    |

### 不确定的地方
- 「Softmax 的温度系数」看不出归属，建议保留为 H1，需你确认
```

### 2.3 主代理复核与分歧回炉

主代理拿着提案逐条核，每条分三档：

| 档位 | 处置                              |
| -- | ------------------------------- |
| 采纳 | 直接进映射表                          |
| 驳回 | 在 `outline.md` 写一句理由即可，不必回问     |
| 存疑 | **回炉**：把分歧点 + 该处稿子原文丢回同一子代理重看一轮 |

回炉用**同一个子代理**（它已有信号包的上下文，不必重发）：

```text
上一轮你建议：
{子代理原话}

我的复核意见：{主代理的判断}
理由是：{理由}

以下是该处的稿子原文（前后各 30 行）：
---
{稿子原文}
---

请只针对这一处重新判断：{具体要回答的问题}
其余已确认的映射保持不变，不要重发整张表。
```

- **回炉上限 2 轮**。两轮下来还不一致 → 主代理拍板，并在 `outline.md` 的「重排记录」里写明分歧点与最终取舍。
- 回炉只问**具体分歧点**，不要笼统地让它「再想想」——那只会得到一份措辞不同、结论相同的表。

## 3. 操作范围（严格边界）

**允许**——只针对标题行：

- 调整层级（`##` ↔ `###`，含升级与降级）
- 改写标题文字（去掉「（续）」这类切分残留、让命名风格统一）
- 删除被合并掉的重复标题
- 在**段落边界**插入新标题（当一个 H1 实际覆盖了两个主题时，拆开它）
- 同步更新标题里的序号

**禁止**——碰正文的任何一部分：

- ❌ 改写、增删、移动正文段落
- ❌ 改动公式、代码块
- ❌ 改动图片引用、图注说明
- ❌ 改动「画面时间」「课件第 N 页」标注
- ❌ 为了迁就新结构而重排内容顺序（这会违反 `notes-prompt.md` 第二节「严格按授课顺序」）

### 判据（一句话）

> **重排前后，去掉所有标题行之后，正文应当逐字相同。**

第 6 节有对应的命令行自检。

## 4. 怎么从文字稿认出真实结构

**不要凭 `{notes}.md` 自己推断**——那正是失真的来源。回到文字稿，找这几类信号：

1. **老师的显式路标**（最强的信号）
   「我们今天讲三件事」「下面进入第二部分」「关于 X 我们先讲到这里，回过头来看 Y」
   「X 有三个要点」→ 这三个要点是 H2，不是 H1。
2. **反复回指的母题**
   若干小节都回指同一个上位概念（都在讲它的不同侧面、都在和它对比）→ 那个上位概念是 H1，它们是 H2。
   典型形态：B1…B6 每个都自称「B 的某种情形」→ B 是 H1，B1…B6 是 H2。
3. **课件结构**
   章节分隔页、目录页、每页页眉的章节名。合订 PDF 尤其有用——它往往已经给出了权威的大块划分。
4. **主题切换处的过渡句**
   「好，那我们接着看一个不一样的东西」「这个和刚才那个没关系，是另一个话题」→ 这里才是 H1 的边界。
   反过来，「刚才那个 X，我们再补充一点」→ 不是新 H1，是 X 的续。
5. **体量**
   老师花了 30 分钟讲的，和花了 3 分钟顺口一提的，不该是同级标题。

## 5. 执行步骤

1. **备份**：`cp "{title_name}.md" /tmp/before_reorder.md`
2. **出骨架**：跑 2.1 节的字数统计脚本，标出所有可疑 H1。
3. **取独立意见**（5-B 且 H1 ≥ 5 时）：按 2.2 节派诊断子代理，拿回映射表提案。
4. **对照稿子定位真实母题**：按第 4 节的五类信号，从文字稿里读出老师真正的大块主题。**这一步是主代理自己的判断，不能拿子代理的提案代替**——提案是输入，不是结论。
5. **复核提案、回炉分歧**：按 2.3 节分三档处理，存疑的回炉（上限 2 轮）。
6. **定稿映射表**：`旧标题（旧层级）→ 新标题（新层级）`，写进 `outline.md` 的「重排记录」一节，再动手改。
7. **执行**：按映射表只改标题行。
8. **校验层级约束**（`notes-prompt.md` 第六节）：H1 ≤ 10 个、每个 H1 下 H2 ≤ 10 个、不出现 H5/H6。
9. **自检**：跑第 6 节的两级自检。

### 拿不准时

- **优先做「降级合并」**（把碎的收进母题），少做「拆分」——合并是收敛操作，错了也只是粒度稍粗；拆错了会破坏授课顺序。
- 老师本身就是平铺的小主题串讲、没有母题时，**保持原样**，不要硬造母题。
- 单个 H1 内部顺序有疑问时，**不动**——顺序问题不属于这一环的职责。

## 6. 自检（两级）

### 一级：归一化后逐字比较

剔除标题行、去行尾空白、压缩连续空行之后比较——这三样全是重排的正常副产品，不该报警：

```bash
cd "<outdir>"
norm() { grep -v "^#\{1,6\}" "$1" | sed 's/[[:space:]]*$//' | cat -s; }
norm /tmp/before_reorder.md > /tmp/before_body.txt
norm "{title_name}.md"       > /tmp/after_body.txt
diff /tmp/before_body.txt /tmp/after_body.txt && echo "✓ 一级通过：正文逐字相同"
```

三步归一化各自挡掉一类误报：

| 步骤                        | 挡掉的误报                            |
| ------------------------- | -------------------------------- |
| `grep -v "^#\{1,6\}"`     | 标题行本身（调层级、改文字、删重复都是改它们）          |
| `sed 's/[[:space:]]*$//'` | 行尾空格                             |
| `cat -s`                  | 删标题留下的多余空行、插标题新增的空行——**最常见的误报源** |

> 为什么用 `^#\{1,6\}` 而不是 `^#\{1,6\} `：后者要求 `#` 后必须有空格，`#标题`、闭合式 `# 标题 #`、行尾带空格的标题都会漏网被算成正文。代码块里的 Python 注释两边都会被剔除，互相抵消，不影响比较结果。

一级通过 → 直接跳到第 ③ 步，不用再看 diff。

### 二级：有 diff 时按判据分类

一级不通过**不等于失败**——重排确实可能要连带删点东西。先把 diff 存下来逐处看：

```bash
diff -u /tmp/before_body.txt /tmp/after_body.txt | tee /tmp/reorder_diff.txt
```

按优先级依次判定，命中前几档就接受，落到最后一档才回退：

| 优先级 | 差异类型   | 判据                                                       | 处置                      |
| --- | ------ | -------------------------------------------------------- | ----------------------- |
| 1   | 空白     | 只有空行增减或行尾差异（一级已过滤，一般到不了这）                                | 接受                      |
| 2   | 标题行残留  | 差异行以 `#` 开头                                              | 接受（标题本来就能改）             |
| 3   | 冗余过渡句  | 被删行 **< 200 字** 且含「接着 / 继续 / 上面说到 / 我们回到 / 前面讲过 / 刚才」之类的 | 可接受，但要在 `outline.md` 登记 |
| 4   | 其他非空增删 | 不属于以上三类                                                  | **回退该处**                |

第 3 档举个例：「（续）编码器」这个标题一旦合并掉，它下面紧跟的「我们接着上一节继续讲编码器」就成了废话——删掉才对。这类连带删除合理，但要留记录便于事后核对。

**回退只撤 diff 指出的那几处**，不要把整份重排推倒重来：

```bash
# 先看清楚动了哪几处（过滤掉 diff 的 +++/--- 头）
grep -n "^[+-]" /tmp/reorder_diff.txt | grep -v "^[0-9]*:+++\|^[0-9]*:---"
# 确认只有这几处要撤，手工改回；确实改不干净才整体回退：
cp /tmp/before_reorder.md "{title_name}.md"
```

### ③ 层级与配图未受影响

```bash
# 层级分布
grep -o "^#\{1,6\}" "{title_name}.md" | sort | uniq -c
# H1 数量（应 ≤ 10）
grep -c "^# " "{title_name}.md"
# 图片引用数、图注数应与重排前一致
grep -c "!\[" "{title_name}.md"
grep -c "^> 画面时间\|^> 课件第" "{title_name}.md"
```

### ④ 重排后的骨架读一遍

确认它现在讲得出「这门课讲了几大块，每块下面分了什么」，而不是一串平铺的小节名。

- [ ] H1 ≤ 10 个，每个 H1 下 H2 ≤ 10 个，无 H5/H6
- [ ] 没有带「（续）/ 补充 / 其余部分」的 H1
- [ ] 相邻 H1 不再同属一个母题
- [ ] 一级自检通过，或二级 diff 已逐处判定完毕
- [ ] 重排记录（含与子代理的分歧点）已写进 `outline.md`

## 7. 常见错误

| 错误                  | 后果                     | 正确做法                         |
| ------------------- | ---------------------- | ---------------------------- |
| 只看 `notes.md` 不对照稿子 | 用失真的结构去修失真，改完还是错的      | 必须回到文字稿，按第 4 节信号重新定位母题       |
| 顺手改了正文              | 破坏「严格按授课顺序」，可能丢内容      | 只改标题行，改完跑第 6 节两级自检           |
| 拿子代理的提案当结论          | 把「没看过全稿的意见」当权威，反而引入新失真 | 提案是输入不是结论，主代理必须自己对照稿子核一遍     |
| 一级 `diff` 有输出就整体回退  | 几十分钟的重排白做，重来一遍还是同样结果   | 先按二级判据分类，只撤真正误改的那一处          |
| 回炉时笼统说「你再想想」        | 拿回一份措辞不同、结论相同的表，白等一轮   | 只问具体分歧点，并附上该处稿子原文            |
| 回炉超过 2 轮还在来回        | 收敛不了，时间全耗在往返上          | 主代理拍板，在 `outline.md` 记录分歧与取舍 |
| 为了结构好看移动段落          | 知识点被搬离老师讲到的位置          | 只调层级，不动内容顺序                  |
| 硬造母题                | 老师本来是平铺串讲，被安上不存在的层级    | 没有母题就保持原样                    |
| 重排后不更新序号/交叉引用       | 标题写着「3.2」但位置已经变了       | 标题带序号的一并同步更新                 |
| 把「拆分」当首选            | 拆错位置会切断老师的一段完整讲解       | 优先降级合并，拆分只在母题边界非常明确时做        |
